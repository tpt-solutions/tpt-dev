# tpt-dev-mock

Mocks for traits, generated by an attribute. Expectations match on arguments, calls are counted, and a missing or unexpected call fails the test.

- **One attribute:** `#[mock]` on a trait generates `MockTrait`, which implements the trait.
- **Expectations:** `mock.method.expect().with(matcher).times(n).returns(value)`, or `returns_with(closure)` to compute the answer from the arguments.
- **Call counts and verification:** `calls()` reports the count, and `verify()` panics if a `times` expectation was not met.
- **Unexpected calls panic:** a call that no expectation answers fails the test.
- **`no_std` with `alloc`:** the runtime needs `alloc`, for boxed expectations, and has no dependencies beyond the macro crate.

## Example

```rust
use tpt_dev_mock::mock;

#[mock]
pub trait Sensor {
    fn read(&self, channel: u8) -> u16;
}

fn total(sensor: &dyn Sensor) -> u32 {
    u32::from(sensor.read(1)) + u32::from(sensor.read(2))
}

let mock = MockSensor::new();
mock.read.expect().with(|a| a.0 == 1).times(1).returns(100);
mock.read.expect().with(|a| a.0 == 2).times(1).returns(23);
assert_eq!(total(&mock), 123);
mock.verify();
```

## Limits

- **Owned arguments and results.** Argument and return types must be `'static`, so references in signatures are not supported.
- **No generic traits or methods, no async methods.** These are rejected with a compile error.
- **No associated types or constants.** Traits that have them cannot be mocked yet.
- **Matchers see arguments, not history.** A matcher is a closure over one call's arguments.
- **Compile-time benchmark not run.** The mock has no measurement against `mockall`, so no build-time comparison is recorded.
