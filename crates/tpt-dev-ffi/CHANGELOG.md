# Changelog

All notable changes to `tpt-dev-ffi` are documented in this file.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). The crate follows [Semantic Versioning](https://github.com/tpt-solutions/tpt-dev/blob/master/VERSIONING.md).

## [Unreleased]

### Added
- Typestate `Session` with `Closed`, `Open` and `Streaming` states for stateful C-style APIs.
- `Backend` trait that describes a library's create, open, start, stop, close and destroy operations.
- `Failed`, which returns the session unchanged together with the library's `Code` when a transition fails.
- Release on drop: the library object is destroyed exactly once, in any state.
- `Handle<T>`, a non-null, typed pointer to a library object.
- `Code`, the status code from the C side, with `Code::OK` and `is_ok`.
- `Session::with` for library calls that do not change state.
- Zero-copy `View` and `Session::with_view` on streaming sessions, with `Backend::view` as the optional source of bytes.
- Compile-fail tests (`trybuild`) for calling `start` on a closed session, and for a view escaping its call or session or coexisting with a library call.
- An integration test with an `extern "C"` library, checked against a `tpt-dev-automata` machine and a header generated by `tpt-dev-headers`.
- The crate is `no_std`, with an optional `std` feature.
